# 올팍 Go! · Olpark Go!

**올림픽공원 공연·날씨를 반영한 주차 혼잡도 예측과 맞춤 방문 가이드**

[라이브 데모](https://davidok7.github.io/olpark-go/) · [NEO AGENT 10초 진단기](https://davidok7.github.io/olpark-go/funnel/) · [GitHub @davidok7](https://github.com/davidok7)

> 2026년 공공데이터 활용 경진대회(한국체육산업개발㈜) 출품 프로토타입.
> 이 저장소에는 올팍 Go! 본편과, 같은 방식으로 만든 NEO AGENT의 셀러 자동화 진단기(`/funnel/`)가 함께 있습니다.

---

## 1. 무엇을 하는 서비스인가

올림픽공원은 KSPO DOME(14,594석), 티켓링크 라이브 아레나(5,003석), 올림픽홀(2,454석), 우리금융아트홀(1,184석), 88잔디마당에서 연중 공연이 열립니다. 공연이 있는 날에는 시작 2시간 전부터 주차장이 포화되고 주변 도로가 정체됩니다.

그런데 공개된 주차 정보는 두 가지뿐입니다.

- **지금 몇 대가 주차되어 있는지** — 3개 문 합계 숫자 하나
- **예상 이용률** — 주말 한정, 전 시간대 동일 값

그래서 "내가 갈 시간에 얼마나 붐빌지", "어느 문으로 들어가야 덜 기다리는지"는 알 수 없습니다.

**올팍 Go!** 는 방문 날짜·시간대·공연장·날씨를 입력받아 이 물음에 답합니다.

1. **시간대별 예상 주차 점유율**(여유 / 보통 / 혼잡 / 만차)과 24시간 예측 차트
2. **12개 주차구역별** 예상 점유율 · 입차 대기시간 · 공연장까지 도보 시간
3. 공연장 앞 구역이 만차면 **한 블록 떨어진 구역**을 대안으로 추천하고, 주차가 어려우면 올림픽공원역(5·9호선) · 한성백제역(9호선) · 몽촌토성역(8호선) 중 도보 시간을 고려한 **우회 동선** 제시
4. **공연 전 90분 · 공연 후 60분** 맞춤 산책·휴식 코스 제안

기존 서비스와의 차이는 화면 안에서 나란히 비교해 보여줍니다(3개 문 합계 실시간 숫자 vs. 구역·시간대별 예측).

## 3. 주요 화면과 기능

### 올팍 Go!
- **방문 조건 입력** — 날짜, 시간대(24개), 공연장, 날씨(맑음·비·눈), 이동수단
- **혼잡도 결과 카드** — 예상 점유율·단계·한 줄 안내, 실시간 3개 문 현황을 함께 표시
- **24시간 예측 차트** — 하루 흐름에서 공연 시작 전후 피크가 어디인지 확인
- **구역별 추천 표** — 12개 구역의 예상 점유율, 입차 대기시간, 공연장까지 도보 시간
- **지금 가장 나은 선택** — 조건에 맞는 구역 1곳과 그 이유
- **만차 시 우회 지하철** — 3개 역 도보 시간 비교
- **공연 전후 코스** — 도착 후 90분 / 인파 분산 60분
- **공연 라인업 · 공공데이터 출처 · 연계 아키텍처 · 예측 로직** — 심사·검증용 정보를 화면 안에 함께 공개

### 셀러 자동화 진단기 (NEO AGENT)
- 3문항 입력 → **AI 대체 가능 비율**, **월 절약 가능 시간**, 업무별 **합본 프롬프트** 생성
- 결과 프롬프트를 클립보드로 복사해 바로 사용
- 1인 대표·셀러가 자기 반복 업무를 스스로 진단하는 입구 역할

## 4. 사용 기술

| 영역 | 내용 |
|---|---|
| 프런트엔드 | **바닐라 JavaScript(ES6+) · HTML · CSS**. 프레임워크·번들러·빌드 도구 없음. `index.html`을 열면 그대로 동작 |

| 예측 | 공연 규모·도착/출차 분포·날씨 계수를 조합한 결정론적 점유율 계산(서버·DB 없음) |
| 배포 | **GitHub Pages** 정적 호스팅 |
| 제작 방식 | **AI 에이전트와의 대화형 바이브코딩** — 문제 정의, 데이터 해석, 화면 설계, 예측 로직, 배포까지 대화로 구현하고 결과는 브라우저에서 직접 확인하며 수정. 필요한 부분만 손으로 고치는 방식 |

실시간 주차현황은 한국체육산업개발이 공개한 API(`https://www.ksponco.or.kr/online/main/parkingorsApi.do?apiKey=PARKING21803504`)를 브라우저에서 직접 호출해 표시합니다. 응답이 없으면 예측 모델 값으로 대체됩니다.

## 6. 예측 방식

```
점유율(h) = min(100, (기본수요(h) + 공연수요(h) × 날씨계수) ÷ 전체 주차면 × 100)
공연수요(h) = Σ (관람객수 × 자가용분담률 0.22 ÷ 평균승차인원 2.8)
              × 도착분포(공연 3시간 전 ~ 10분 후) − 출차분포(종료 후 90분)
기본수요(h) = 2025년 연계데이터의 시간대별 입차 구성(주중·금·토·일 24시간 곡선)
날씨계수   = 맑음 1.00 / 비 1.14 / 눈 1.26
구역점유율 = (구역면 × 기본점유 + 공연차량 × 공연장 근접도 가중치) ÷ 구역면
대기시간   = f(구역점유율) : 70% 미만 0분 · 70~85% 선형 · 85% 이상 급증
```

프로토타입의 시간대별 기본 곡선과 계수는 공개 데이터의 구성 항목을 기준으로 설계한 **잠정값**이며, 2025년 원 데이터 전체를 확보하는 대로 회귀 보정합니다. 화면에 표시되는 값은 예측치이며 실제 주차 상황과 다를 수 있습니다.

## 7. 프로젝트 구조

```

app.js            예측 엔진과 화면 렌더링
funnel/           NEO AGENT 셀러 자동화 진단기(단일 HTML, 스타일·스크립트 내장)
```

빌드 과정이 없습니다. 저장소를 받아 `index.html`을 브라우저로 열면 동작합니다.

## 8. 운영 원칙

- 서버·DB 없이 GitHub Pages 정적 호스팅 → 2028년까지 유지 비용 없음
- 예측 결과는 하루 1회 배치로 7일분을 사전 생성(계획) → API 장애 시에도 직전 값으로 서비스 유지
- 회원가입·앱 설치 없음, 개인정보 수집 없음
